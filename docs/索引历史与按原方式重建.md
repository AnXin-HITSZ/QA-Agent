# 索引历史与按原方式重建

## 存储

0015新增三张MySQL表；任务与文件结果长期保留，不再按最近50个裁剪。

- rag_index_jobs：按知识库namespace和job_id保存任务摘要、范围、状态、时间、策略和冻结的执行计划。
- rag_index_job_files：按namespace/job_id/ordinal保存精简逐文件结果，包含document_id、原件哈希、实际请求的extraction_options、结果与短原因。
- rag_index_version_files：按namespace/version/key_hash保存已准备版本的逐文件策略；只有当前发布指针引用的版本才是生效依据。

namespace由桶、原件根前缀和Qdrant基础集合派生。开发/生产数据库各自保存历史；不在MySQL存完整正文。
联合版本rag_search_releases.files及Elasticsearch文档同时增加document_id与extraction_options，正文仍存OSS和Elasticsearch。
非联合索引也记录版本配置，之后启用全文搜索可以复用。准备后未发布的配置不影响当前生效配置。

## 提取配置与重建

长期复用extraction_mode及mixed_invoice，覆盖native_only、general、general_advanced、invoice、payment_record。
refresh_ocr是单次操作，重建默认false；用户仍可通过手动索引入口明确强制刷新。
提取配置按文件复用，切块策略使用当前配置。支持整库、分类子树和显式文件清单；前端提供整库/当前分类计划入口。

POST /admin/knowledge/rebuild-plan返回当前版本、固定原件清单、逐文件配置、模式统计、未知/不支持数量和计划token。
POST /admin/knowledge/rebuild-jobs携带scope、token、overrides；token不匹配返回409，未知支持格式未补选返回400。
不支持格式（包括明确跳过的ZIP）展示为跳过，不能算正文已覆盖。缺失原件阻止该计划执行。
任务排队后再核对版本与原件清单，全部文件写入一个候选版本，统一校验并一次发布；不会按提取方式分别发布。
初次建立联合索引仍要求整库范围。FILE_SEARCH_ENABLED=true时同时建立全文、快照和向量；false时仅维护原向量路径及版本配置。

## 旧数据补齐

先迁移0015，再运行scripts/import_index_history.py --apply，导入仍保留的JSON/JSONL任务；幂等导入，不覆盖已有SQL状态，不删除原记录。
已经被旧50任务策略清理的历史无法恢复，不宣称导入了全部过去任务。
旧逐文件配置优先从当前版本记录读取；缺失时核对实际向量中保留的index_version和content_sha256，
只接受对应代际的Redis已发布清单，或同版本成功任务中明确indexed的文件结果。失败任务与不匹配的后续配置不覆盖当前版本。
回退后从回退版本读取策略；无法核实的文件显示待确认，不默认推断native_only。

## 历史查询与运维

GET /admin/knowledge/index-jobs支持offset/limit/job_status，GET /index-jobs/{id}/files支持明细分页，全部受管理员权限保护。
生产MySQL故障不静默降级写本地历史；创建失败释放锁，执行失败保留可排查状态。未配置MySQL的兼容环境仍可走旧JSON路径，但没有永久历史或按原方式重建。
文件锁通过独立guard串行化检查和更新，防止两个worker同时占锁；启动对账不打断其他仍存活的执行进程。
发布/删除恢复凭据继续保存在INDEX_STATE_DIR。未完成恢复记录不按时间清理；applied发布记录90天后可清理。
任务业务历史永久保留，原有应用运行日志不迁入任务表；本次不改变systemd/journald日志保留规则。

## 部署

先提交、推送、ECS拉取；确认无索引任务，应用两库0015；导入各环境仍保留的任务历史，最后重启后端及发布前端。
不重跑既有迁移，不执行down。此次实现和部署不自动重建真实知识库或开启付费OCR。
生产和开发的FILE_SEARCH_ENABLED暂保持false；Elasticsearch已配置，真实首次联合重建应在确认逐文件计划后启用该开关并执行。
