# 文件搜索与联合索引

## 查询契约

现有 `search_knowledge` 的切块检索和上下文预算不变。新增：

- `search_files_literal`：文件名、路径或提取正文严格子串匹配。多个词以 all（AND）或 any（OR）组合；连续短语传单个完整值。空白不隐式合并，通配符转义。
- `search_files_semantic`：完整字面集合 A + 全文 CJK 相关性召回 + Qdrant 文件分组向量召回。向量分别查询完整主题和明确字面词。补充按文件去重、RRF融合，剔除 A 后复用现有重排序客户端。A 不精排、不按相关分数裁剪，按路径排序；补充附命中方式和证据。候选上限只作用于补充，语义不保证穷尽。
- `get_file_search_page`：按结果集 ID、offset 取后续页。结果绑定登录用户，过期或跨用户统一不存在。

主回答 LLM 决定明确关键词和 AND/OR；组合主题建议 AND，用户指定条件优先。无独立判定 LLM，无逐文件语义审计。重排失败或未配置时保留 RRF 补充顺序并报告降级。全文/向量补充一路故障不会丢 A；字面搜索失败、分片失败或超时拒绝返回“完整”结果。

## 数据与版本

- OSS 原件继续是事实源。新 `OSS_TEXT_PREFIX` 默认为 `rag-text/`，必须与原件/SOP 前缀分离，不允许嵌套在其下。RAM 必须具备该前缀写读权限。
- 快照 JSON 保存完整提取正文、自然单元及页码/章节。地址包括原件哈希、提取配置指纹及提取结果哈希；强制 OCR 重跑产生不同结果时不覆盖旧快照。
- Elasticsearch 每文件一条完整记录。`body`/`name` 用内置 cjk 分析器做全文相关性检索；`body_literal`/`name_literal`/`key_literal` 用 wildcard 字段做连续字符匹配。正文不使用受短字符串上限影响的 `.keyword`，不按切块拆成文件清单。
- Qdrant 仍保存切块；为 oss_key 建 keyword payload 索引，按 oss_key 分组，每文件取三个证据片段。
- MySQL 0014 增加四表：联合发布记录、逻辑知识库指针、用户搜索结果集、分页条目。发布记录保存文件版本/快照元数据，不保存完整正文；分页条目只保存有限证据。

索引任务同时准备两套候选索引，范围外正文从上一完整 Elasticsearch 版本复制。首次启用只能全库重建，不能从旧向量切块拼出假“完整正文”。文件提取失败或任一索引写入失败不发布；两套候选验证完成后以 MySQL 短事务 CAS 切换共同发布指针。每次搜索固定同一发布记录。旧本地 manifest 仅为兼容镜像，镜像失败不能删除已提交的生效索引。回退校验两个目标存在后，以 CAS 同时切换。

已发布 Elasticsearch 索引不可变，search_after 遍历完整字面结果；不会受默认前 10000 条展示窗口限制。完整字面清单及补充结果持久化，分页不再重新检索/重排，不预签下载 URL。首次结果构建成本与匹配数量相关，但不下载全库正文，也不逐文件调用模型。

每次搜索只枚举 OSS 文件元信息，文件名/路径覆盖新上传且未提取的文件。正文只使用与 OSS 大小、修改时间一致的版本；未提取、跳过、失败、过期的正文计入 uncovered。页/导出重查原件，删除或修改后隐藏旧证据。此处沿用现有 OSS 秒级 mtime 校验：同秒同大小外部覆盖仍有漏检风险，不声称内容级强一致。直接修改 OSS 后必须重新索引。

联合模式不再执行旧的自动“两代之外删除”，避免删除被分页或回退持有的版本。运维清理必须保留 active/previous、未过期搜索所引用版本及正在构建版本；先删除无引用的搜索记录/版本，再做快照引用清理。当前没有自动快照垃圾回收，失败任务可能留下可核验的 OSS 快照，需纳入容量维护。

## 接口与前端

普通登录用户可 POST `/api/v1/knowledge/search`，GET `/search/{id}` 翻页，GET `/search/{id}/export` 导出 CSV。导出逐页重新校验原件，转义电子表格公式前缀；中途故障中断响应，不伪造完整清单。下载仍用现有鉴权下载接口，点击时签短效 URL。

知识库页使用现有 SelectField、颜色/圆角/暗色 tokens。聊天回答附文件结果卡片，保留字面/补充分组、总数、覆盖情况、证据、分页和导出；SSE 和非流式均支持。历史轨迹可恢复卡片，但结果集过期后需要重新搜索。当前首页与工具文本仅带当前页，不能把聊天上下文当全量文件清单。

## 配置与启用

本地及 ECS `.env` 仅补缺失配置，不覆盖已有值或凭据。`FILE_SEARCH_ENABLED=false` 默认保持原问答索引逻辑；未配置 Elasticsearch 时搜索明确不可用。

1. 按用户约定先 commit、push，ECS 仓库 pull。
2. 在 ECS 的 qa_agent_dev 与 qa_agent_prod 应用 `0014_rag_file_search.up.sql`。不重跑 0001–0013，不执行 down。
3. 配置 Elasticsearch 8.x 或 9.x REST 服务；API Key 优先，否则用户名密码。默认验证 TLS，自签名 CA 配置 `ELASTICSEARCH_CA_CERTS`，不关闭证书校验。为受控索引前缀授予创建、写入、搜索、删除权限。
4. 配置 OSS 独立快照前缀权限，保留已有 `RERANK_*`。
5. 开启 `FILE_SEARCH_ENABLED`，重启后端，执行一次全库索引。首次联合版本发布前，问答继续使用旧向量版本，文件搜索不可用。

Elasticsearch 尚未提供，不能宣称真实全文服务已验证；未自动打开功能或重建正式知识库。真实 Ragas 评测仍等待用户完成上传并确认题目答案。
