# 一键记忆评测脚本

## 默认运行

先在一个终端保持 `bash start-dev.sh` 运行（复用其 MySQL 隧道）；另一个 Git Bash 终端在项目根目录执行：

```bash
bash eval-memory.sh
```

自动执行 build → ask → score → report。默认数据是 backend/data/eval/datasets/locomo/locomo-smoke.json，三组为 no_memory、memory、full_context，全量历史字符预算为 100000；回答模型及提取模型沿用 backend/.env，裁判显式复用回答模型。构建、回答、裁判均有费用，脚本会提示，不需要逐步输入命令。

脚本自动生成唯一 run-id，并在 backend/data/eval/last-run.json 保存最近 ID，开始时显示目录，每阶段显示开始和结束时间。运行前检查 app_env=dev、qa_agent_dev、user_memory_eval_dev 以及记忆表/0008 字段/0006 状态表主键。检查集合配置不等于提前验证 Qdrant 连通，构建与召回会进行实际检查。100000 字符并不是模型 Token 窗口保证；仍应检查 full_context 的 skipped 与检索 degraded。

Git Bash 自动使用本机 qa-agent Python 路径；其他机器使用当前 python，可通过 QA_AGENT_PYTHON 指定解释器。无需 conda activate，脚本使用 certifi 设置证书，并为 Qdrant/localhost 补 NO_PROXY，不改变 .env。脚本不会启动隧道或前后端，不会执行数据库迁移。

## 全量数据集评测

原始文件放在 `backend/data/eval/datasets/locomo/locomo10.json`，执行：

```bash
bash eval-memory.sh --full-dataset
# 全量但不调用裁判（构建和三组回答仍有费用）
bash eval-memory.sh --full-dataset --no-judge
# 预览全部步骤，不适配、不连接服务、不付费
bash eval-memory.sh --full-dataset --dry-run
```

`--full-dataset` 自动执行 prepare（sample-limit=0，不设置 question-limit），再 build/ask/score/report。包括原始文件中所有样本、历史会话和五类问题（含不可回答类），不是 Mem0 论文四类问题设置的严格复现。准备完成后显示实际样本、会话和题目数；完整适配数据单独保存在本 run 的 prepared-dataset.json，不覆盖小样本文件。

原始路径可用 `--full-dataset --input <路径>` 指定，相对路径仍以 backend 为基准。不能同时传 --dataset。`--action full` 表示完整工作流，`--full-dataset` 才表示全部数据，两者不同；不带该选项仍是原来的小样本。

默认预算仍为 100000 字符，不保证所有样本完整历史都放得下。预算不足的 full_context 问题会跳过并记录，不能把截断结果当全量历史。全量每题最多有三次生成和三次裁判，另有构建及召回调用，费用明显增加。本次实现只做离线验证，未执行真实全量评测。

全量中断后恢复构建：`bash eval-memory.sh --action build --run-id <原ID> --dataset data/eval/runs/<原ID>/prepared-dataset.json`；后续 ask/score/report/status/purge 使用原 ID 即可，不用再传 --full-dataset。

## 查看进度、清理命令

另开终端在项目根目录执行：

```bash
bash eval-memory.sh --action status
```

自动查看最近实验；显示已登记任务数量、最近任务、认领次数、错误、有效记忆条数和已有构建摘要。尚未入队的会话不在任务数里。需要查看旧实验：

```bash
bash eval-memory.sh --action status --run-id locomo-events-20261009-193841
```

默认保留服务端数据和本地报告，不自动 purge；完成分析后清最近实验：

```bash
bash eval-memory.sh --action purge
```

或 `--action purge --run-id <ID>` 清指定实验。底层仍按 eval scope 清理，不删除整集合；本地文件保留。

## 常用选项

```bash
# 仅显示命令计划，不读配置、不连库、不调用模型、不创建实验文件
bash eval-memory.sh --dry-run

# 不使用付费裁判；构建、回答仍然付费
bash eval-memory.sh --no-judge

# 指定已适配的数据集（相对路径以 backend 为基准）
bash eval-memory.sh --dataset data/eval/datasets/locomo/locomo-smoke.json

# 指定新实验 ID / 预算
bash eval-memory.sh --run-id locomo-test-001 --context-chars 100000

# 已完成 build 后，只重新生成三组答案（覆盖 results.json；需重新评分）
bash eval-memory.sh --action ask --run-id locomo-test-001

# 重新评分并生成报告（默认裁判会付费）
bash eval-memory.sh --action score --run-id locomo-test-001

# 仅重新生成报告，本地操作
bash eval-memory.sh --action report --run-id locomo-test-001
```

`--action build` 可单独构建；恢复已有构建时应传同一数据集路径和 run-id，底层会核对构建身份及幂等状态。原始 locomo10.json 需先使用既有 prepare 命令适配，本脚本不自动放大样本量。默认 full 拒绝覆盖已有目录；协议变更后必须新建 run-id。

阶段非零退出时停止后续步骤并保留数据；Ctrl+C 中断也不会清理，先 status 检查任务与租约再决定恢复。runner.json 记录最后执行动作，不保存凭证；完整有效性与模型口径仍以 build.json、run.json、results.json、scores.json 为准。脚本完成只代表 CLI 步骤退出成功，不保证每题回答正确或所有模式都有有效答案，需检查报告失败/跳过和降级。
