# 事务记忆与关联图

QA-Agent 面向实验室与课题组行政管理。本次先实现报销材料准备、办理进度和经历追溯，不接入学校审批或支付系统，不是实验记录平台。

## 最终职责

- 私人事实、偏好与背景：现有 MySQL + Qdrant，两路召回/RRF/重排序继续工作。
- 报销事务：MySQL 保存稳定事项、精确金额字符串、材料、待办和当前状态。
- 情景内容：追加办理事件、确认来源和更正说明，不由 LLM 自动覆盖历史。
- 事务图：Neo4j 保存可重建关联投影。前端展示事项中心图，查询后按 MySQL 当前版本及对象核验；不可用或过期时明确回退权威数据。
- 正式制度：仍从 SOP/知识库获取，历史经历不能变成制度或权限依据。

旧通用图提取、统一事实图抽取、语义图召回排序及路径组合代码已删除。存量表、隔离、同步/清理台账仍保留用于撤回旧数据，不再创建新的通用图任务。旧 LoCoMo 图结果是历史实现的评测，不代表本次事务模块效果。

## 数据模型

0011 建立四张表：

| 表 | 职责 |
|---|---|
| admin_matters | 当前事务与版本、归属、软删除 |
| admin_matter_events | 追加事件、操作前后快照、来源、请求幂等标识 |
| admin_matter_links | 材料、项目、人员、待办，解除关联不删除外部文件 |
| admin_matter_projections | 持久化待投影版本、已发布版本、失败与重试次数 |

所有读写按登录用户隔离。当前只管理本人事项，没有课题组共享 ACL；经办人名称不是授权身份。管理员不能通过本接口跨用户读取。

金额保留 Decimal 精度、限制为 CNY，JSON 保存十进制字符串。模型只提供草稿，Pydantic 校验后仍需用户确认保存。当前只有 reimbursement 类型；新增采购等类型需要专属 Schema、状态转换、制度与工具，不只修改 Prompt。

## 状态与材料

准备中 → 用户确认提交 → 用户确认审批通过 → 用户确认已支付；提交/审批中的事项可以记录退回，退回后补件再确认重新提交。取消只能从明确允许的状态执行。

提交必须已有金额、用途，并满足用户登记且带制度来源的材料要求。没有登记材料清单不等于已经符合真实制度。材料状态区分 reported（仅口头说已有）、provided（提供引用）、verified（用户记录已核验，必须提供来源）；系统目前不做文件上传、发票真伪或正式制度自动核验。

缺件自动生成关联待办；补件后同一待办完成，不重复生成。自动待办不能随意解除。普通关联任务与现有 Redis 待办抽屉属于不同存储，当前在事务详情中维护，未伪装成已经完成双向同步。

事件只追加。更正新增 correct 事件，不能无痕修改原事件。事务版本冲突返回 409。请求标识若复用到不同操作也返回冲突。

## 图投影与失败恢复

MySQL 事务提交业务数据与投影意图，外部 Neo4j 调用在事务之外。后台每30秒处理待同步事务。失败保留意图和错误类型；图关闭期间仍正常管理事务，恢复开启后继续补同步。

后台每5分钟按游标对账最多20个已发布事务，逐项比较对象正文/类型、根版本/状态及关系，发现漂移只重置该事务且版本仍一致的投影标记，下一轮重建；不通过点数比较声称一致，也不触发 Embedding。

图根节点使用 (user_id,id) 唯一约束。Neo4j 事务先获取根写锁，再核验版本，拒绝旧版本覆盖。删除发布清空对象和边，但保留不含业务正文的版本墓碑，拒绝迟到旧快照复活。发布成功后只有 MySQL 当前目标版本仍一致才确认发布，期间有并发编辑则继续同步新版本。

关联图默认最多显示 MEMORY_GRAPH_MAX_NODES 个对象，办理事件显示最近50条，裁剪显式返回；全部关联和历史仍可在详情与时间线查看。Neo4j 投影保留完整关系，不随前端展示预算丢数据。

## 前端及 Agent

“事务管理”提供列表、详情、材料与待办、时间线和 SVG 关联图。点击事项或项目/经办人节点进入字段编辑；点击材料/任务节点进入受约束的关联编辑；事件节点进入追加更正流程。没有任意关系画线编辑器。

Agent 新增只读事项列表/详情工具。归属来自 chat 路由的可信身份配置，模型没有 user_id 参数，不能越权查询。创建、状态变更等仍由前端确认操作，模型不会自动提交审批或支付。

## 配置与 ECS 更新

MEMORY_GRAPH_ENABLED 名称和值保留，但语义改为事务图投影及旧图清理；它不再控制私人事实的抽取协议或图召回。

保留 NEO4J_URI / USERNAME / PASSWORD / DATABASE 和连接超时、查询超时、连接池、MAX_NODES、SYNC_BATCH；不新增模型或凭据。

删除六个配置：

```ini
MEMORY_GRAPH_EXTRACT_RETRIES
MEMORY_GRAPH_MAX_HOPS
MEMORY_GRAPH_MAX_PATHS
MEMORY_GRAPH_FANOUT_LIMIT
MEMORY_GRAPH_CANDIDATE_K
MEMORY_GRAPH_MAX_ENTITIES
```

MAX_NODES 改为前端图展示对象预算；SYNC_BATCH 改为每轮事务同步数，同时供存量撤回投影分批使用。本地 .env 已沿示例顺序和注释重新对齐，现有其余值、模型、密钥、测试集合及图总开关值均保留。ECS .env 本次未修改。

## 安装与验证

先备份开发或生产数据，迁移 SQL 不会在应用启动时自动执行。

```bash
cd /root/qa-agent/backend
# 使用拥有 DDL 权限的管理账号；明确指定应用库，勿复制开发库名到生产。
mysql <应用数据库名> < migrations/0011_administrative_matters.up.sql
python scripts/memory_graph.py init
python scripts/memory_graph.py health
# 后续按原部署方式重启应用，保持凭据不变。
```

本地开发可使用：

```bash
cd /d/Projects/QA-Agent/backend
conda activate qa-agent
python scripts/check_administrative_matters.py
pytest tests/test_administrative_matters.py tests/test_administrative_api.py -q
```

开发账号若无 DDL 权限会报1142，需管理账号在 qa_agent_dev 应用SQL，不应为了验证改账号权限。guarded --apply-dev-migration 仅允许 dev + qa_agent_dev。

登录前端“事务管理”：新建事项 → 登记带来源材料要求 → 检查自动缺件任务 → 提供材料 → 核对任务完成 → 确认提交 → 记录带来源退回 → 补件重提 → 查看图/时间线。并发编辑应409，访问他人的事项应404。

```bash
python scripts/memory_graph.py status --user-id <本人ID>
python scripts/memory_graph.py sync --user-id <本人ID> --matter-id <事项ID>
python scripts/memory_graph.py audit --user-id <本人ID> --matter-id <事项ID>
python scripts/memory_graph.py rebuild --user-id <本人ID> --matter-id <事项ID>
```

旧通用图如需撤回，先备份，按具体用户执行，无全库删除：

```bash
python scripts/retire_legacy_memory_graph.py --user-id <用户ID> --scope ''
```

此命令不删私人文本/向量记忆，取消并清理旧图任务内容，撤回旧图事实和投影；Neo4j不可用时保留持久化清理意图。应用本次不会自动删除生产旧图数据。
