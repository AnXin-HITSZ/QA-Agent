# 记忆图基线诊断（2026-10-10）

对象：无图基线实验 `backend/data/eval/runs/locomo-nograph-allq-20261010-143259`（**只读**，未改动其中任何文件）。

目的：在实现记忆图（Neo4j 投影）之前，把基线的失分**逐题归类到具体机制环节**，作为实现步骤1～6的阶段验证依据，并明确哪些失分与图记忆无关。本文是开发 / 诊断材料，不是生产规则，也不是对客观准确率的声称（见 §5 防过拟合与使用边界）。

## 2. 产物能回答与不能回答的问题

能：某条 memory_id 是否进入 `retrieval_trace` 的 validated / fused / rerank_input / rerank_returned / final；每题 `evidence[]`（含 `vector_rank` / `bm25_rank` / `trimmed`）、`degraded[]`、`context_chars`、诊断文件（按 session / job 的提取 & 维护快照，19 个）。

不能（本次新增诊断要补的缺口，§18）：

1. **无 dia_id / 轮次级溯源**：记忆只有 session 级 `thread_id`，无法把一条记忆映射回具体对话轮；
2. 未出现在任何名单里的记忆，其“为什么没召回”（距离差 vs 被过滤）没有记录；
3. memory 模式没有数字化的 `budget_chars / truncated` 字段（只有 degraded 文本与 `evidence[].trimmed`）；
4. 计数题没有“同一轮重复提及 vs 独立事件”的结构化依据（无 source_count / 无事件去重标记）；
5. diagnostics 是提取/维护结果 JSON 字符串，未结构化；且按 session 而非按题存放；
6. 逐题无法归因成本（usage.by_purpose 是时间窗汇总，可能混入其他调用）；
7. judge 无逐题提示词快照；Q116 这类“额外信息是否编造”的分歧只能人工对照原文；
8. 提取/维护过程不可见（Q93 的“压缩”只能看到压缩后文本）。

## 3. 失分九阶段归类（机制诊断）

阶段定义：1 事实未提取 / 维护中丢失；2 已保存但未进候选；3 已召回但在融合/重排入口被截断；4 进重排但未进 final；5 证据不足（客观不够）；6 答案未用对上下文中的证据；7 字符预算截断；8 服务降级；9 参考答案 / 说话人 / 图像 / judge 存疑。
（同题可命中多阶段；题号均经产物重算核实。）

## 4. 对实现的启示（写入技术方案的依据，不写具体题的规则）

1. 阶段 2/3/4 的共性：**候选被融合截断**、**跨会话/跨消息关联缺失**、**多对象枚举不完整** → 对应第三通道（实体/关系/事件链接 → 图候选）、候选准入与配额、枚举纪律、计数纪律。
2. 阶段 1 的共性：**关系与参与者丢失**（Q93/Q10）、**指代与跨消息对象无关联**（Q72）→ 对应图元素提取（实体/关系/事件 + 参与者 + 来源）与消歧（存疑保持待定）。
3. 阶段 6/7/9 **不是**图能解决的：需要 (a) 证据组合与预算策略更诚实（7）；(b) 评分协议核验与人工复核（9）；(c) 回答阶段对证据的使用是模型行为，只有通用改进可做，且不得按题调（6）。
4. 论文口径与本项目口径不同：不可把 LoCoMo 论文数字或 Mem0 论文数字与本结果互推。

## 5. 防过拟合与使用边界（§2）

- 本文所有案例**只用于机制诊断与阶段验证**；不得作为生产提示词示例、不得据此写关键词/人名规则、不得作为实体/别名/关系标注来源、不得修改测试记忆或参考答案。
- 生产提示词保持通用；回归测试一律用独立编写的合成场景（与本文案例无关）。
- 本样本（conv-26）是**开发/诊断集**；后续未参与调优的样本用于泛化验证，结论必须分开报告。不得仅凭本样本宣称整体改进。
- 本文用于设计“诊断记录什么”（§18）：实体匹配、指代证据、图路径、逐通道名次、融合与候选准入、重排输入输出、预算排除、降级与错误阶段 —— 全部为通用字段，无数据集特定分支。
