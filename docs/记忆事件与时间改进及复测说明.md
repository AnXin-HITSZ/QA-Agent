# 记忆事件与时间改进及复测说明

## 共享记忆行为

本次更新对正式聊天和评测使用同一套提取规则，不针对题目、答案或标准证据优化。

- `preference`：偏好；`profile`：背景或当前属性；`event`：具体经历、历史事件；`task`：重要计划、目标与进度，包括有后续价值的一次性安排。
- 一条事实表达一件事，保持来源语言、姓名、数值、否定、条件及时间。计划不等于完成；不同日期的事件分别保存。
- 助手建议、假设、寒暄、普通临时指令、秘密，以及引用的 SOP／知识库正文仍不进入个人记忆。记忆不授予权限，不替代业务事实库，也不自动创建待办。
- 提取协议 `mem-extract/3`；维护协议 `mem-maintain/2`。结构不合法及来源 ID 不合法均有限重试；内部元数据不允许由模型直接提交。

## 时间与来源

迁移 0008 为 `memory_items` 增加 `fact_context JSON`，为 `memory_history` 增加 `old_context`、`new_context`。旧记忆保留空元数据，不从入库日期补造历史。

`fact_context` 保存：

```json
{
  "time": {
    "raw": "昨天",
    "anchor": "2023-05-08T13:56:00",
    "start": "2023-05-07",
    "end": null,
    "precision": "day",
    "status": "resolved"
  },
  "state": "completed",
  "sources": [{"message_id": "D1:3", "speaker": "小安", "recorded_at": "2023-05-08T13:56:00"}],
  "conversation_id": "eval:locomo:sample:s1",
  "turn_id": "eval:locomo:sample:s1"
}
```

记录时间、事件时间和 `created_at/updated_at` 分开。原始时间表达必须能够在引用的用户消息中核实，否则只保留原文并标记 `unverified`。

确定性解析支持完整年月日、年、月、中英文昨天／今天／明天、上／下个月、去／明年，以及明确的日期范围；其余表达保留为 ambiguous。多个来源的记录时间不一致时，不选一个任意锚点。没有锚点不使用服务器当前日期。月精度不会生成某月 1 日，年精度不会生成 1 月 1 日。

事件或计划解析得到的日期附加到新事实正文，使现有向量与关键词检索能访问日期；同时保存原始表达与精度。既有向量模型、BM25、RRF、重排序流程及参数没有更改。正文未改而仅元数据变更，沿用 `meta_version` 和只刷新 payload 的机制，不重新调用 Embedding。

历史事件或计划不得因后续进展而 UPDATE／DELETE。维护器误提议这种操作时，整份提议改为独立 ADD 新事实；不会执行半份原决策。历史纠正需同时有模型明确的 `correction=true` 和来源中的显式纠正表达。该语言规则是保守检查，不保证自动理解所有纠正语句；未通过时保留旧事实并新增，用户仍可手动编辑或删除。

来源元数据合并保留此前来源。正文改写、删除审计附带元数据快照；彻底清除按原 `(user_id, scope)` 范围一并脱敏这些快照。

## 评测调整

三种模式共用 `eval-answer/2`，明确输出简短英文，无法得知时也用英文回答。正式聊天回答语言不受该指令影响。

LoCoMo 输入说明 `locomo-extract-note/2` 仅解释两人姓名前缀、记录时间与消息 ID，不放宽共享记忆标准。历史构建不读取题目、参考答案或 evidence。

每个构建任务在本 run 的 `diagnostics/<job-id>.json` 保存提取阶段与维护决策记录，构建结束保存 `memory_snapshot.json` 和 `history_snapshot.json`，包含该 run 的有效与软删除记忆及变更审计。正式 Worker 不启用该诊断导出；生产终态任务仍清空临时正文。诊断文件可能包含评测历史事实，不能公开发布，`purge` 清服务端测试数据后本地文件仍保留，需按原有本地归档策略处理。

诊断时逐题检查：原始历史是否有支持 → 提取阶段是否保存 → 维护操作是否丢失或覆盖 → 当前记忆是否存在 → `results.json` 实际上下文是否召回 → 回答是否使用。日期标注冲突单独记录，不改原数据来迎合参考答案。

## 升级与复测

应用不会自动改表。先备份 dev 数据库，停止旧 Worker，使用迁移账号手动执行：

```sh
cd /d/Projects/QA-Agent/backend
mysql --default-character-set=utf8mb4 -h 127.0.0.1 -P <隧道端口> -u qa_migrate -p qa_agent_dev < migrations/0008_memory_fact_context.up.sql
```

前提是 0001–0007 已按项目迁移顺序执行。0008 down 会丢失新增时间与来源元数据，回滚前先备份。

继续使用 dev MySQL、测试记忆集合 `user_memory_eval_dev` 和已检查的 Redis。不要修改生产集合或复用旧实验 run-id。构建身份现在包含提取与维护协议版本，旧 run 仅保留作基线。

```sh
conda activate qa-agent
export EVAL_RUN_ID="locomo-events-$(date +%Y%m%d-%H%M%S)"
python scripts/memory_eval.py build --dataset data/eval/datasets/locomo/locomo-smoke.json --run-id "$EVAL_RUN_ID" --sleep 1
python scripts/memory_eval.py ask --run-id "$EVAL_RUN_ID" --modes no_memory,memory,full_context --context-chars 100000 --answer
python scripts/memory_eval.py score --run-id "$EVAL_RUN_ID" --metrics f1,bleu1,judge --judge-use-answer-model
python scripts/memory_eval.py report --run-id "$EVAL_RUN_ID"
```

`100000` 是这次约 70906 字符历史的字符预算示例，不是模型 token 窗口保证。执行前核对回答模型的实际上下文窗口及输出预算；超窗不可截断后继续称 full_context。确认 full_context 没有 skipped，memory 没有召回／重排降级，并人工检查关键失败题。

模型调用会产生费用；本次实现仅运行离线替身测试，没有执行上述付费实验或实际数据库迁移。分数改善仍需新的真实实验验证。

完成分析后可清本 run 的服务端数据：

```sh
python scripts/memory_eval.py purge --run-id "$EVAL_RUN_ID"
```

无需新增前端删除接口；既有 purge 仍负责作用域隔离和可恢复向量清理，不删除整个集合。
