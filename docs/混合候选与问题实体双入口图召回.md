# 混合候选与问题实体双入口图召回

当前检索协议为 graph-recall/4。事实与图结构的统一抽取、MySQL权威存储、Qdrant及Neo4j投影不变，无新增迁移。

## 检索流程

向量和关键词召回先经过MySQL归属、状态及版本校验，再按基础RRF排名选取少量种子记忆。通过权威图快照中的已确认提及、关系两端及事件参与者取得实体，不额外调用LLM识别实体。

另一入口仍从问题匹配实体名称和别名。两入口交替合并并去重，受到同一实体总量、节点、路径、跳数、邻居及查询总耗时限制。图结果再次通过MySQL版本校验，加入RRF融合和重排序；保留基础候选池，最终按证据组合及上下文预算注入回答模型。图故障降级不阻断向量与关键词结果。

## 配置

仅新增一个数值参数，不增加功能开关：

```ini
MEMORY_GRAPH_SEED_MEMORY_K=3
```

范围0–20。0只保留问题实体驱动图召回；3表示取通过校验的混合候选排名前3条记忆。更多种子不保证更好，可能增加噪声和遍历竞争。MEMORY_GRAPH_MAX_ENTITIES=8现在约束两入口合并后的实体总量；其余图预算继续复用。总开关仍为MEMORY_GRAPH_ENABLED。修改配置后重启进程。

本地.env与.env.example均已加入该参数，顺序和注释一致，保留既有配置与凭据。ECS可在MEMORY_GRAPH_MAX_ENTITIES之后补入上述参数；本次未部署或修改ECS配置。评测manifest记录seed_memory_k和graph-recall/4，不能与旧协议直接归因比较。
