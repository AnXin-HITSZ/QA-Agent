# 长期记忆评测入口审查（2026-10-09）

## 结论

当前 `backend/scripts/memory_eval.py` 是 CLI 评测脚本，不是独立 HTTP 评测接口。已满足基础冒烟、隔离构建、问答对照和证据导出；尚不满足完整 LoCoMo 效果评测与论文指标对比要求。

## 已具备

- build / ask / run / purge；隔离 scope 和派生评测用户，正式 worker 与评测 worker 分开。
- no_memory / memory / full_context 三种对照；回答模型复用现有配置。
- 保存数据集、模型与部分检索参数、回答、参考答案、类别和检索证据。
- 构建只读取 conversations，不读取参考答案；额外检查测试问题原文泄漏。
- 记录构建任务、索引状态和评测清理结果。

## 完整评测前需要补充

1. **LoCoMo 适配**：当前只接受自定义 conversations/turns/user/assistant 与 questions 格式。原始 LoCoMo 顶层为样本列表，不能直接传给 load_dataset。应保留 sample、speaker、session 时间、dia_id、类别和 evidence；明确两位说话者到评测主体的映射，不能直接把双方当成用户/助手而丢失人物身份。
2. **时间和顺序**：exchanges 目前仅传文本、subject 和 thread_id，未传原会话时间。批量登记任务后按 next_run_at 排队，同值时没有明确次序保证。对时间题和偏好更新题，应提供可验证的历史顺序与原始事件上下文。
3. **自动评分**：没有 F1、BLEU-1、LLM 裁判、分类型汇总和重复运行的统计。参考答案目前只是导出字段。
4. **运行有效性**：build.drained 只排除 pending/running/index_pending，没有要求 failed 为零；cmd_run 在构建未完成时仍执行 ask，末尾才返回非零。正式结果应单独标明失败构建，避免计入正常质量汇总。
5. **映射校验**：未知 conversation_id 会回退到全部历史和默认主体；缺省 subject 会合并不同会话。完整基准应严格校验映射并拒绝错误关联。
6. **性能与费用**：当前记录字符数，不是上下文 Token；没有逐题检索/回答延迟及 p50/p95。usage_stats 按时间窗与用途汇总，可能混入其他用户调用，也不包含回答模型费用，无法作为完整 run 费用。
7. **消融与证据评测**：没有单次运行内的有/无 Reranker 对照，也未计算标准 evidence 的召回指标。需先保存原消息到记忆来源的映射，再定义压缩记忆的证据召回口径。
8. **错误与复现**：逐题模型调用异常可能中断 ask；没有逐题断点恢复。manifest 只记录 HEAD，不能区分未提交代码的变化；全量上下文的字符预算只标注而不阻止超出模型窗口的调用。

ask 的 docstring 中“零模型调用”不准确：不带 --answer 只是不生成答案，memory 模式仍可能调用 Embedding、查询改写 LLM 和 Reranker。计费应以真实调用日志为准。

本轮仅审查评测实现，未修改其行为，未执行付费评测。
