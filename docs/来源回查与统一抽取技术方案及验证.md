# 来源回查、有界补检索与统一抽取

本轮扩展参考图记忆综述的分层来源、事件结构和有界多轮检索思路，同时实现用户提出的统一抽取。不是论文复现，不声明等价或效果提升。旧结果保留，默认开关全部关闭，不修改真实 .env。

## 写入链路

默认仍为 mem-extract/5 → 维护 → 已入库事实的图提取。启用 MEMORY_UNIFIED_EXTRACT_ENABLED 且图写入生效后，切换 mem-unified-extract/2：同次 LLM 调用读取原始对话，同时输出简洁事实、来源摘录、实体、关系、事件。Pydantic 校验结构；摘录必须来自引用的 user 消息，图名称和属性由摘录核验。不是用共现证明关系正确，语义错误仍需评测。

原文支持的图候选保存在权威事实的 fact_context.structured_graph，协议 raw-grounded-graph/1。通过既有 ADD/UPDATE/DELETE/NONE 维护、版本 CAS 和代次闸门后入库，再由图 Worker 确定性生成投影，不再二次调用图模型。图失败不回滚已提交事实，沿用持久任务重试。手工添加或没有统一结构的旧事实仍可走旧图提取。

维护协议 mem-maintain/5 比较简短正文及精确结构。UPDATE 合并新结构；NONE 不擅自更改模型维护结论，因此被判为完全重复的候选仍可能没有新增图信息，这需要验证。手动改变正文会撤销旧统一结构，避免旧图精度重新覆盖用户更正。

事件描述仍用事实正文，参与者、对象、角色和属性独立保存。时间由既有后端按来源锚点解析，不让图模型再次猜日期。未解决的同名身份仍保持 pending，不能为了提高召回合并。当前不实现跨事件或跨消息的独立全局指代解析器。

## 来源存储与读取边界

0010 新增 memory_episodes。只有显式打开 MEMORY_SOURCE_STORE_ENABLED 才保存 user 来源，不保存 assistant/tool 输出；疑似秘密采用既有启发式过滤。原文作为参考证据，不能直接写成权威事实或权限信息。统一抽取的必要来源摘录随事实长期保存，与独立片段的限期保留不同。

片段按 user/scope/generation 隔离，保存消息 ID、说话者和记录时间。默认最多100个活跃片段、30天保留；读取只允许未过期、当前代次、且关联有效记忆的片段。过期即不可检索，下次保留片段时限量清空过期或超量正文；并非数据库自动 TTL 删除。撤销/过期/超量行保留空正文的幂等标识到 purge，避免重复导入复活。

普通删除和手动改写会撤销相关来源轮次，清空正文。一个轮次中多个事实共享片段时，采取保守整轮撤销，可能降低其他事实回查能力。彻底删除沿用原 purge，清除片段、图、事实及相关数据，返回 episodes 删除数。关闭开关不替代删除；purge 即使关闭开关也清理已存在的来源表。回滚先关开关，再执行0010 down；down 会丢弃来源证据。

不会自动从 Redis/聊天历史偷偷导入。旧构建可用 memory_sources.py 显式导入，脚本只读取历史，检查已完成构建、数据摘要、qa_agent_dev 与 user_memory_eval_dev，拒绝已purge的run；问题、参考答案、标准证据不会进入数据库。来源表未应用迁移时不能启用。

## 检索链路与预算

MEMORY_EVIDENCE_ROUNDS=0 保持原三路召回。1 启用关键词来源召回与原问题重排。2 最多一次结构化 LLM 规划，最多两条带原问题约束的补查询；已有事实保持版本校验，补查询的事实重新按原问题重排。规划不产出答案、不写事实，不执行模型生成的 SQL 或工具指令。

来源读取有片段数及字符上限，BM25 仅做候选生成，Reranker 校对原问题相关性。按相邻完整消息组成片段，保留局部指代上下文；并不保证恢复跨会话指代。来源最多占总 MEMORY_CONTEXT_CHARS 的一半，仍受 MEMORY_SOURCE_CONTEXT_CHARS 限制。最终事实数仍受 top_k 约束，总参考块不扩大预算。来源启用会改变事实与原文的预算分配，所以消融轴是 evidence，不能将结果单独归因于图。

记录补查询、缺失维度、候选来源ID、最终片段、预算上限和失败。来源或规划异常保留首轮证据并标降级；评测比较拒绝将服务故障视为正常因果对照。来源关键词机制对跨语言、同义词和低词汇重合仍有局限。

## 配置（修改后重启进程）

```ini
MEMORY_SOURCE_STORE_ENABLED=false
MEMORY_SOURCE_SEARCH_ENABLED=false
MEMORY_SOURCE_RETENTION_DAYS=30
MEMORY_SOURCE_MAX_EPISODES=100
MEMORY_SOURCE_MAX_CHARS=30000
MEMORY_SOURCE_CANDIDATE_K=12
MEMORY_SOURCE_CONTEXT_CHARS=1000
MEMORY_EVIDENCE_ROUNDS=0
MEMORY_UNIFIED_EXTRACT_ENABLED=false
```

读取已保存来源可以 store=false/search=true，存储关闭不自动删除旧片段。统一抽取还需要 MEMORY_GRAPH_ENABLED=true 和 MEMORY_GRAPH_WRITE_ENABLED=true；master关闭不触发统一图抽取，也不连接Neo4j。Maintenance 检索不触发来源或规划，以避免递归。

### HTTP读取异常补充

真实构建曾出现StreamConsumed并由任务重试恢复。离线复现发现用量探针吞掉首次读取的TransportError，会使SDK再次读取已消费的流而掩盖原始错误。修复为记录尝试后传递原异常，保留SDK正常重试；SSE/非JSON保持原有调用方读取行为。此路径可复现，但不声称已确认本次网络异常的唯一原因。

统一协议v1曾因事件attributes类型错误中止完整构建，数据保留；v2增加通用JSONSchema和空对象/数组约束，不放宽校验。v2一会话真实冒烟和完整构建通过；问答按用户后续要求改为先验证前20题，结果见下节。

### 逐题失分与诊断

- Q14：原始来源补回针对特定群体的咨询/心理健康职业方向，修正基线因“尚未最终决定”而完全拒答的问题。裁判对“decided”和“still figuring out”措辞存在解释空间，结果仍应人工复核。
- Q19：原先完整的山地/海滩/森林证据中，森林事实被优化组预算选择排除；加入邻接原文后占用空间，造成已答对列举退步。单纯增加原文不是收益保证。
- Q16、Q20：列举覆盖不足。泳游、恐龙展等事实已经存在于238条记忆中，但对应问题的最终上下文没有覆盖全部必要项目；不能把这类失败归因于提取没有保存。原文补检索虽然补回部分活动，仍未做到跨会话穷尽。
- Q3、Q15：当前回答指令只依据证据、不使用外部知识；开放域职业推断与反事实“Likely no”要求可能超出该评测回答约定。应另行定义类别一致的推断规则，不能为了参考答案让生产个人事实提取器编造推断。
- Q6：标准证据D2:1原文明确写“last Saturday”，参考答案却写Sunday。当前两组保留Saturday而被判错，属于需人工复核的标注冲突。没有修改参考答案、评分或原文来提高成绩。

### 预算口径与下一步

MEMORY_CONTEXT_CHARS配置为2000，来源片段配置上限1000，最终事实上限6条。实际历史格式化流程在正文预算之外追加记忆标签与全局参考说明；本轮最终参考块平均基线2287.6字符、优化2019.15字符。因此2000目前不能理解为整个最终系统提示的严格字符上限。两组配置预算一致，但格式化开销核算不完全相同，后续应先统一渲染后预算口径，再做预算敏感性实验。

来源块在当前策略中优先预留空间，可能挤掉高价值事实；补检索后的来源候选仍优先保留原问题首轮候选，在候选上限下新增来源未必进入最终重排。下一步应按信息增量、证据重复和完整列举/关系链选择来源，而不是固定预留一半空间；不要仅增加top_k或上下文长度后归因于图增强。开放域评测规则和参考标注问题应独立处理。

当前未证明净准确率提升，且检索延迟约2.81倍。新功能默认关闭，未修改生产.env、未部署、不建议直接开启生产补检索。统一抽取已验证实际构建与图同步能力；其效果收益仍需同历史、不同抽取构建的独立对照和未用于优化的样本验证。
