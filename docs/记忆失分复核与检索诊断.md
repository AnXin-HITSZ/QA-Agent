# 记忆失分复核与检索诊断

## 本轮变化

共享提取与维护提示增强来源语言、并列角色、原子事实要求，不添加类型前缀。协议更新为 mem-extract/5、mem-maintain/4；仍需真实实验检验提示遵守情况，不宣称已强制保证语义完整。

相对时间与可信来源记录时间一起展示。ambiguous 只代表未转换成精确日期，不代表没有时间依据；可按原有精度作答。没有修改 last week 为某个具体日期的解析规则。正式记忆上下文与三组评测统一遵守此要求；eval-answer/3 仍仅影响评测回答。

评测 results.json 的 memory 模式新增 retrieval_trace：validated（归属、版本校验后的两路名次）、fused（融合排名及 RRF 分数）、rerank_input（实际送入模型的 ID）、rerank_returned（供应商返回的排名与分数）、ranked（重排及回退续尾顺序）、final（预算和版本检查后最终 ID）。未返回的候选没有虚构重排分数；未配置或失败时某些字段可以不存在。正式调用默认不记录 trace，不导出被权限校验过滤的 ID。评分与回答不使用 trace。

## 人工标注

在实验目录放 annotations.json，report 命令自动附加人工复核区；不改原数据、答案、指标或分母。例如本次原文 D2:1 明确是 last Saturday，参考答案却为 Sunday：

```json
{
  "run_id": "locomo-events-20261009-193841",
  "entries": [
    {
      "question_id": "locomo:conv-26:q6",
      "kind": "reference_conflict",
      "note": "D2:1 原文为 last Saturday，参考为 The sunday before 25 May 2023；保留原始评分，单独人工复核，不迎合参考改写事实。"
    }
  ]
}
```

标注允许 reference_conflict、metric_mismatch、manual_review，题号必须存在且 run_id 一致。标注不进入构建或回答提示，不能使用人工结论优化具体测试题答案。

## 复测

不需要新迁移、依赖或改变 top_k。重新构建须新 run-id（提取及维护协议已改变）；保留旧实验。先以既有记忆执行新 run 的 ask 可诊断回答和检索变化，但不得称为新提取规则实验；正式完整复测应新建 build，再 ask --modes no_memory,memory,full_context --context-chars 100000 --answer、score、report。

查某条 memory_id 是否在 validated 中；不在表示未进入通过校验的召回候选；在 fused 而不在 rerank_input 表示融合头部或输入预算排除；在输入而不在 returned 表示模型未选回；在 ranked 而不在 final 表示 top_k、预算或并发版本检查排除。必须结合 degraded 与实际候选排名解释，不能只凭数量判定原因。
