# 记忆页面与计量体验修复说明

2026-10-14。本次无数据库迁移、无.env配置变更，不修改数据库中的历史时间或生产数据。

## 记忆能力与时间

后台保存记忆并不依赖模型的写入工具。此前系统提示仅提供只读检索参考，模型因此错误地推断平台不能保存；现在每轮注入真实的存储配置状态，说明完整回答后后台自动提取、可在“我的记忆”编辑删除、并非每句话都保存、不能提前承诺已经成功。记忆能力问题无需查SOP。未配置存储时不承诺跨会话保存。

每次生成由后端注入当前北京时间（UTC+08:00），不增加时间工具调用。聊天登记的来源消息携带同一显式+08:00时间锚点，避免北京时间零点附近把今天解释成UTC的前一天。历史消息仍使用自身日期。

created_at、updated_at和indexed_at由服务/Worker用UTC写入MySQL DATETIME，不由LLM生成。问题是API序列化缺少时区标记，浏览器当成本地时间，产生8小时偏差。现在记忆行和历史审计时间返回显式UTC的Z或+00:00，再由浏览器转换本地时间。后台轮次原已带时区，因此此前看起来与记忆行相差8小时。不同记忆间数秒的差异仍可能来自实际后台处理时间。事件发生日期与保存/更新时间不是同一个字段。

## 管理搜索与交互

管理页面使用MySQL正文搜索，与聊天自动混合召回分离。空白分隔的词项需全部出现在正文中，不区分大小写；百分号和下划线按字面值处理。过滤用户、scope和active状态，更新时间倒序分页，total为匹配总数。既有待索引记忆仍可搜到，管理搜索零Embedding/Reranker/图调用。没有新增搜索结果表，后端每次查询权威事实，前端仅将当前结果暂存在内存ref中，刷新或重新搜索会替换，不写入用户记忆。

输入220ms防抖后自动搜索，清空自动恢复列表，移除“回到列表”。加入请求序号，旧请求不能覆盖新搜索或登出后的列表；命中词高亮。记忆编辑/删除保留文字动作但增加矩形背景和键盘焦点轮廓；记忆搜索与聊天侧栏使用自定义清除按钮，替换浏览器原生搜索叉号。

## 调用与费用统计

概览四卡固定184px，统计四卡固定300px；超出内容内部滚动并可键盘聚焦，移动端也保留稳定尺寸。按服务卡显示记录数、失败数和真实HTTP请求数；重试可能令请求数超过记录数。

用量与费用按服务同行展示，各单位用量与各币种金额分别列出，不能把单位和币种凭空配对。部分未知用量/费用另列，不计为0。计量覆盖Embedding、OCR、长期记忆的LLM与重排序，不包含聊天主链路LLM；原统计说明仅写Embedding/OCR已过时，现在改为常驻脚注。

缓存按层与单位统计：ocr_raw是OCR原始结果复用，ocr_text是本地文本转换复用，embedding是文本对应向量复用。hit直接命中，miss需计算，shared等待他人计算后复用，skipped同批重复去重。这不是供应商Prompt Cache、不是对话记忆召回命中；不同层命中不能直接换算成节约请求数或金额。按天以UTC日期分组，条长表示调用记录数，红色表示当天有失败；时间筛选按浏览器本地时间换算查询边界。统计说明不再需要点击展开，价格表维护仍保留折叠区。
