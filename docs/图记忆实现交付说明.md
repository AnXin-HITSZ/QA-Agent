# 图记忆实现交付说明

## 实现范围

在已有图表、仓库与提取协议基础上接入了运行链路：记忆变更登记图整理任务，Worker 保存可复用提取阶段，MySQL 事务提交图事实与同步台账，再发布 Neo4j。图召回加入原有语义、关键词、RRF、重排序管线，候选经过权威版本校验，多条路径证据按完整组合选择。

管理 CLI 提供健康、状态、补建、重建、对账、修复、失败重试、人工消歧及评测 run 清理。总开关关闭时检索不连接 Neo4j；编辑和删除保留清理意图，恢复后台后补做。

同一个固定构建支持命名实验变体，产物分别保存在 variants 目录；前后检查记忆/图摘要。比较工具校验代码、数据、模型、检索条件、评分协议及答案摘要，图故障的结果不算正常有图实验。

迁移：`backend/migrations/0009_memory_graph_tables.up.sql`；服务配置：`docker-compose.neo4j.yml`。两者均未实际执行。

## 使用与限制

逐步部署、消融、比较和清理命令见《图记忆部署与消融评测指南》；数据模型和开关矩阵见《记忆图索引技术方案》。固定服务版本为 Neo4j 5.26.0 Community。

当前消歧保持保守：同名不自动合并，依据不足的提及保留 pending，可由明确的管理操作确认。查询实体使用名称/别名匹配，不额外调用模型。图不能补回基础提取器遗漏的事实，效果尚未证明。

图整理按批执行，并携带有限同线程事实；每个 owner/scope 的投影原子替换，持有 SQL 状态锁，活动记忆超过 10000 条时明确拒绝而不静默截断。更大规模需进一步分区设计；部署后应实测锁等待、并发接管和删除恢复。
