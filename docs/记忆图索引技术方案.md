# Neo4j 图记忆索引技术方案

## 定位与事实边界

MySQL 是权威事实源；Qdrant 与 Neo4j 都是可重建索引。图组件不另建一套 Mem0 的事实维护系统，也不替换原有 ADD / UPDATE / DELETE / NOOP 维护。默认关闭，通过环境配置并重启进程生效。

```text
用户消息 → 原有提取与维护 → MySQL 记忆 + 同事务登记 graph_extract
    → Worker 图整理 → MySQL 实体、关系、事件、来源 + 同事务登记 graph_sync
    → Neo4j 原子发布

问题 → 向量召回 + 关键词召回 + 实体匹配/有界图遍历
    → MySQL 当前版本校验 → 三路 RRF → 候选覆盖 → Reranker
    → 完整证据组合选择/预算 → 再次版本校验 → 回答模型
```

图整理只读取已保存的事实及其来源元数据，不能凭空恢复原事实提取阶段遗漏的内容。生产提取器的个人记忆边界不变，不把 SOP、知识库或工具正文复制成个人记忆。本轮不加入 LoCoMo 人物、职业、关系或参考答案的专用提示。

程序校验编号、枚举、引用、摘录与来源文本，并不证明模型的语义判断一定正确。尤其是实体同一性、关系方向及事件合并，仍需实际评测与审计。图遍历仅找证据，不推导新的可传递关系，不作为权限依据。

## 模块与数据模型

`backend/app/memory/graph/`：

| 模块 | 职责 |
|---|---|
| base / disabled / neo4j_client | 开关、生命周期、原子投影、遍历与逐条对账 |
| tables / models / repo | 七张权威表及 SQL 读写 |
| extract | `mem-graph-extract/2`，Pydantic 输出约束与有限结构重试 |
| runtime | 事务内登记、来源维护、版本快照、同步与召回入口 |

迁移为 `0009_memory_graph_tables.up.sql`，不在应用启动时自动建表。

| 表 | 职责 |
|---|---|
| memory_entities | 稳定 ID、类型、名称、隔离边界、代次、状态及版本 |
| memory_entity_aliases | 已接受的别名，不能用别名唯一性强行合并人物 |
| memory_entity_mentions | 原文提及、事实来源、已消歧/待定状态与候选证据 |
| memory_relations | 有方向的关系、实体或文本宾语、状态和时间 |
| memory_events | 独立事件、描述来源、时间表达/锚点/精度、参与状态和属性 |
| memory_event_participants | 事件参与者和角色，可保留未绑定实体的名称 |
| memory_fact_links | 关系或事件与多个记忆来源、revision/meta_version 的对应 |

复用 `memory_jobs` 的 `graph_extract` 和 `memory_ops` 的 `graph_sync`，不新增消息队列。正式 Worker 只处理正式 scope；评测 Worker 只处理指定 eval scope。

## 开关矩阵

所有子开关受 `MEMORY_GRAPH_ENABLED` 约束。图 Worker 依附于原有记忆 Worker，生产自动执行还需 `MEMORY_WORKER_ENABLED=true`。`MEMORY_WRITE_ENABLED=false` 暂停提取任务，删除/索引收尾仍执行。

| 总开关 | 写 | 查 | 后台 | 行为 |
|---|---|---|---|---|
| false | 任意 | 任意 | 任意 | 不连接 Neo4j、不抽取、不投影、不召回；已发生删除仍保留 SQL 清理意图 |
| true | true | false | true | 构建与同步图，不参与回答召回 |
| true | false | true | false | 只读已构建图，适合固定构建消融 |
| true | false | false | false | CLI 无图消融，召回不连接 Neo4j |
| true | false | false | true | 只处理既有同步/删除操作，不新增图提取 |
| true | true | true | true | 完整链路 |

写开启而后台关闭会积累任务，不能声称图构建完成。关闭期间已有图事实的修改或删除仍撤销 MySQL 来源并登记图清理；重新开启后台后补做。Neo4j 不可用或关闭时，彻底清理不能返回完全成功。

## 提取与消歧

每次模型输出实体必须提供批内 `ref`，同名不同 ref 保留为不同对象；关系用 ref 引用端点，并提供支持关系的原文 `quote`。事件描述直接采用引用事实的正文，时间和状态采用同一事实的元数据。

待执行图任务按用户、scope、thread 合并最多 32 条变更；执行时最多补充同 thread 的 64 条近期有效事实，帮助关联已确认提及。结构化输出立即持久化到任务 stages，重试复用相同协议及相同事实版本的已付费结果。

名称或别名只提供候选，不能单凭唯一名称合并。只有当前输入事实上的已确认提及证明同一实体时才复用；不确定时登记 pending 提及，不强绑关系。可以通过管理 CLI 在明确检查来源后确认待定提及。此策略偏保守，可能降低跨会话实体连接率；评测应分别分析“事实不存在”和“实体未绑定”。

年/月精度保留原有时间 JSON，不补造具体一天；不能解析为完整日期的 start/end 为 NULL，原始范围保存在事件属性 `_time`，精度单独记录。计划、完成、取消等状态分别保存，过去事件不因新状态自动作废。

## 一致性与恢复

1. 记忆变更、图提取任务在同一个 MySQL 事务提交。
2. 模型调用在事务外；续租、claim_token、generation 和事实 revision/meta_version 在提交前复核。
3. 图事实及同步台账同事务提交。某个索引失败不回滚已保存事实。
4. Neo4j 每个 `(user_id, scope)` 投影在单一事务内替换；发布期间持有该用户 scope 的 SQL 状态锁。与修改、purge 串行化，迟到发布不能覆盖较新的代次。
5. 发布后进程崩溃、台账未收尾可重放。发布期间的新变更登记新 pending 操作，不能复用正在运行的操作而丢失同步意图。
6. 召回使用快照摘要，遍历前后核对摘要，最终证据还要重新读取 MySQL 的当前版本。
7. 空闲 Worker 每 300 秒检查最多 20 个实体或事件 owner 的投影，逐属性及边检查，发现漂移登记修复。彻底清空的 scope 可通过指定 owner 的 CLI 对账；清空操作自身也有持久化重试。

当前发布采用 scope 完整原子替换，UNWIND 按 `MEMORY_GRAPH_SYNC_BATCH` 分批提交给同一事务。记忆正文按主键分页读取，单 owner/scope 限制 10,000 条有效记忆，超过时明确失败，不静默截断。此实现适用于当前规模；更大规模需分区增量投影。外部发布期间占用该 owner 的 SQL 状态锁，图服务慢会延长其写入等待，查询和连接均设置超时。

## 检索、证据与预算

查询实体采用规范名/已确认别名在问题中的大小写不敏感匹配，不增加查询 LLM 或实体 Embedding 调用。未匹配实体是正常空结果，不是故障；别名缺失、简称或代词可能无法匹配，这是当前明确的召回边界。

遍历采用有界 BFS。关系通过“主语—关系节点—宾语”表达；事件参与者通过事件节点关联。不会穿过记忆节点继续扩散。限制实体数、结构深度、节点数、邻居数、路径数、候选数及查询总时间；截断写入诊断。

第三路提供记忆 ID 与来源路径，经过 MySQL 当前版本校验后参与 RRF。重排输入为较大候选集，最多预留候选池约三分之一给图候选，随后仍由同一 Reranker 排序。图关闭时保留原有两路检索。

命中路径的多条证据作为组合选择，不能超过最终 top_k 和字符预算。缺成员、超预算、收尾版本变化会撤回不完整组合并解释原因，不无限增加上下文。正常单条记忆仍可使用。

评测 trace 保留匹配实体、路径、访问数、截断、候选版本、融合、重排与最终上下文。生产不把正文写入日志。新增图整理调用使用既有 `memory_extract` 计量用途，每次实际模型调用只记录一次；Neo4j 查询不是供应商模型费用。图故障有明确降级，可继续原有两路召回。

## 删除

普通删除撤销记忆来源与提及，无其他来源支持的关系、事件及参与者移除；共享关系仍有有效来源时保留。原有普通删除审计保留。

彻底清理删除该用户/scope 的七张图表、记忆、来源、任务及历史敏感正文，递增 generation，并保留 Neo4j 清理台账。空投影发布会删除该 owner 所有 Neo4j 节点及关系，不保留 manifest 节点。关闭或故障不能虚报 clean=true。

图整理不新增 Redis 缓存正文，也不新增实体 Embedding 缓存；本轮新增的付费阶段复用记录存在 jobs，彻底清理时一并删除。既有 Embedding 计算缓存遵循原有项目清理语义。

## 消融与验证边界

旧无图 baseline 原始产物不修改。新系统构建图一次，停止 Worker，关闭图写入/后台，在同一 scope 上分别开启与关闭 SEARCH。

`--variant` 将 results、scores、report、manifest 放在独立目录；已有变体拒绝覆盖。固定构建摘要在执行前后复核，变更即失效。比较工具检查数据、题目、回答与评分协议、检索参数及代码摘要，除 SEARCH 外图配置需相同。有图召回故障的结果标无效，不能作为正常图收益。

部署和命令见 [图记忆部署与消融评测指南](图记忆部署与消融评测指南.md)。离线通过不等于真实 MySQL/Neo4j 联调；效果提升必须在真实评测后报告。
